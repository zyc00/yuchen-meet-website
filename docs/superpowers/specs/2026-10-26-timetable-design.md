# Meeting timetable

Use a compact weekly timetable following the availability overview at meet.jiayuanm.com, with the user's explicit Monday-through-Sunday order. Keep the homepage paper, ink and fonts. Use seven date columns and hourly rows (13 rows for the normal 10 AM–11 PM New York schedule), previous/next week controls, muted unavailable cells and a clear selected cell. Align the first page to the Monday of the viewer's current week; retain the final partial week of the booking horizon.

An hour is an overview of the actual half-hour start times, not a synthesized booking slot. Clicking an hour with multiple starts reveals exact choices immediately below the calendar; a single remaining start is selected directly. Every selectable start must come from the API, including for 60-minute meetings. Show distinct UTC offsets for repeated wall times during DST. The existing booking request, calendar integration and recovery behavior remain unchanged. Show the selected date/time below the table with a Continue action to the details form. Fit all seven columns on narrow screens without horizontal scrolling.

Approach: a semantic HTML table with native buttons fits the requested timetable and the existing lightweight frontend. A third-party calendar library would add unnecessary UI and dependencies; retaining the separate day/time pickers would not meet the request. Week paging, compact cell styling and responsive dimensions are implementation choices.

Timezone conversion must retain every actual slot, including repeated wall times during DST and quarter-hour offsets. Empty, loading, closed and failed availability must remain honest and non-bookable. No live test invitations.

Keep all time text on the left axis. Grid cells contain color only, including the selected cell. Use compact rectangular blocks, small gutters, cream availability, blue occupancy, light-blue selection and gray unavailable starts. An hour with different half-hour states uses a continuous split background without another grid border; it must not imply the entire hour is occupied. Exact times remain in accessible names/native tooltips, the inline choices and the selection summary below the calendar. Keep the page at 640px maximum width, place duration/timezone controls on one row, and remove redundant explanatory rows.

Occupancy correction: a missing available start does not imply a calendar event. Only future half-hour intervals overlapping the API's actual `busy` intervals use the blue Busy color. Past starts are faded gray; other disabled starts (closed hours, insufficient room for the chosen duration, horizon boundaries) are gray. Available starts use cream and selection uses light blue. Enumerate UTC half-hours for disabled-state classification so DST and quarter-hour offsets remain correct; only API-provided slots can become buttons.

Keep a server-relative clock advancing while the page is open, including across sleep and refocus. Remove expired buttons and clear an expired selection unless a booking request is already locked. Regression coverage includes elapsed/current starts, duration padding, real interval overlap, cross-midnight and quarter-hour timezones, DST repetitions/gaps, and excluded dates.
